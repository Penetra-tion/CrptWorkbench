# Архитектура CRPT Workbench

Документ сверён с кодом и структурой проекта 2026-09-18. CRPT Workbench — модульный монолит на .NET 10, ASP.NET Core и Blazor Interactive Server. Интерфейс и прикладные сценарии исполняются в одном серверном приложении. Основные задачи: API Console, просмотр сведений о кодах маркировки, профили, история, избранные операции и настройка подключения TraceX.

## Слои и зависимости

```text
Web ───────────────> Application ──> Domain
 ├─────────────────> Infrastructure ──> Application + Domain
 └─────────────────> Clients ──> Domain
```

**Domain** определяет сущности профиля, истории и избранного, перечисления, контракты сведений о кодах, порты репозиториев, секретов, сертификатов, подписи и клиентов CRPT. Не зависит от транспорта, EF Core или интерфейса.

**Application** реализует управление профилями, историю, избранное, реестр операций и выполнение операций. `ApiOperationDescriptor` описывает операцию, `IApiOperationHandler` выполняет её через Domain-порт. True API использует `POST /cises/info` с JSON-массивом без параметра `pg`; демонстрационные National Catalog и SUZ сохраняют GET-контракты. Для добавления операции нужны DTO, descriptor, handler и регистрация в Web.

**Clients** реализует mock-клиенты трёх систем и `RealTrueApiClient`. Здесь находятся получение и кэширование токенов, ограничения исходящих запросов, передача correlation ID и безопасная транспортная диагностика. Application не зависит от этого проекта: выбор реализации происходит в Web.

**Infrastructure** реализует EF Core/SQLite, специализированные репозитории, миграции, Data Protection, рекурсивное маскирование, Windows Certificate Store, CryptoPro-подпись и проверку подключений TraceX. TraceX поддерживает выбор SQL Server/PostgreSQL; это не означает, что основная база приложения уже переведена на PostgreSQL. Инициализация основной базы использует миграции с защищённым принятием известной legacy-схемы.

**Web** содержит точку сборки приложения `Program.cs`, регистрацию зависимостей, конфигурацию, Blazor-компоненты, readiness/live проверки и журналы. Страницы не обращаются напрямую к HttpClient, EF Core, сертификатам, токенам или подписи. Будущие бизнес-модули должны использовать Application и существующие Domain-порты.

## Поток данных и ограничения интеграций

```text
Blazor-страница
  → ExecuteApiOperationService (Application)
  → реестр и обработчик операции
  → клиент через Domain-порт (mock или разрешённый production True API)
  → результат и технический обмен
  → ISensitiveDataMasker
  → репозиторий истории → EF Core/SQLite (Infrastructure)
  → отображение результата в интерфейсе
```

Для одного выполнения создаётся один correlation ID: он проходит через контекст, исходящие заголовки, технический обмен, журналы и историю. Результат включает статус и длительность. Ошибки транспорта преобразуются в прикладной результат; секреты маскируются до сохранения и отображения. История упорядочивается по индексированному `CreatedAtUnixMs`, поскольку SQLite не сортирует используемое отображение DateTimeOffset напрямую; `CreatedAt` сохраняется для отображения.

По умолчанию используется Mock. `MockOnlyNetworkGuardHandler` остаётся первым исходящим обработчиком mock-конвейера и пропускает только `.mock.invalid`. Mock-ответы содержат `X-CRPT-Workbench-Mock: true`. Raw mode — редактор mock-запроса, а не произвольный сетевой клиент.

При явно настроенном `Crpt:Mode=Production` разрешены только True API: `GET /auth/key`, `POST /auth/simpleSignIn`, `POST /cises/info` на фиксированном утверждённом хосте. Production-guard проверяет точные пары method/path, перенаправления отключены, профиль не меняет адрес транспорта. National Catalog использует разрешённые методы чтения карточки и документов. SUZ использует отдельный токен и точный GET квитанций, описанные ниже. Токены хранятся в памяти; обновление синхронизировано, после 401 допускается один повтор с обновлением токена.

Подпись для `/auth/simpleSignIn` выполняет `CryptoProCertificateSignatureService` в памяти как прикреплённую CMS (`detached: false`): исходные байты challenge включаются внутрь PKCS#7, как требует контракт получения токена. Сертификат берётся из `LocalMachine/My`, закрытый ключ не экспортируется. Для ГОСТ Р 34.10-2001 и ГОСТ Р 34.10-2012 сервис вызывает Windows `CryptSignMessage`: CryptoAPI читает привязку сертификата к контейнеру и передаёт операцию установленному CryptoPro CSP. Для негостовых сертификатов, используемых локальными тестами, сохраняется .NET `SignedCms`. Challenge кодируется в UTF-8 без автоматически добавляемого BOM и без изменения исходной строки; буферы исходных данных и готовой CMS обнуляются после использования. Native-вызов не включает флаг подавления интерфейса, что соответствует `silent: false`, поэтому PIN и контекст службы требуют проверки на целевом сервере. `csptest.exe` для этого пути не используется; оставшиеся legacy-поля конфигурации не являются описанием действующего алгоритма.

## Хранение, журналы и эксплуатация

СУЗ: операция `suz.document-status` читает `GET /api/v3/receipts/receipt?omsId={uuid}&resultDocId={uuid}` на `suzgrid.crpt.ru:443`. `SuzTokenProvider` получает отдельный клиентский токен через True API `/auth/key` и `/auth/simpleSignIn/{omsConnection}` с присоединённой подписью сертификатом профиля. Кэш на 9 часов изолирован по профилю, ИНН, сертификату и подключению; устаревший 401 не удаляет обновлённый токен. `RealSuzClient` проверяет разрешённые параметры до авторизации; отдельные HTTP-клиенты запрещают redirects и скрывают секреты независимо от полного логирования. `suz.order-status` остаётся локальной демонстрацией. `SuzDocumentStatusResults` сохраняет неизвестные поля ответа; общий executor маскирует историю, а `SavedResultView` восстанавливает карточки квитанций. Миграция БД не нужна.

`Program.cs` устанавливает текущую директорию и content root в `AppContext.BaseDirectory`. В Mock без явного `Crpt:DataDirectory` база и ключи создаются в `App_Data` рядом с исполняемым приложением, обычно внутри `bin/Debug/net10.0`. Существующая `src/CrptWorkbench.Web/App_Data` сохраняется как локальный каталог данных; наличие этой папки не означает, что текущий запуск использует её. Явный DataDirectory должен быть абсолютным путём.

Production по умолчанию использует `C:\ProgramData\CrptWorkbench`, SQLite `crpt-workbench.db` и key ring в `keys`. Секреты проходят через `ISecretStore`, а Data Protection защищает их; на Windows ключи защищаются DPAPI, в production — в контексте машины. Потеря key ring может сделать зашифрованные секреты недоступными. Базы, ключи и PFX не включаются в исходники и серверный пакет.

Serilog разделяет события интерфейса и сервера: клиентские файлы находятся в `logs/client/client-*.log`, серверные — в `logs/server/server-*.log`; относительные пути разрешаются от каталога данных. Уровни и ротация конфигурируются независимо. При `Serilog:FullLoggingEnabled=false` тексты исключений и недоверенные свойства системных событий не сохраняются; диагностика подписи содержит этап, тип ошибки и HRESULT без challenge, PIN и деталей сертификата. Временный режим `true` передаёт исходные события и дополнительно записывает полные исходящие HTTP-заголовки и тела, поэтому может содержать секреты и предназначен только для краткой диагностики.

`deploy/windows/Build-Package.ps1` выполняет restore, Release build, тесты приложения и установщика, self-contained publish для win-x64 и создаёт `artifacts/windows/CrptWorkbench-win-x64.zip`. ZIP содержит `app`, установку, проверку, восстановление, общий `AccessControl.ps1` и инструкцию. Рабочие данные не упаковываются. Windows Service по умолчанию слушает `127.0.0.1:5080`; обновление и откат сохраняют данные. Проверки ACL и службы описаны в [инструкции развёртывания](docs/deployment/windows-production.md).

`tests/CrptWorkbench.Tests` проверяет операции и DTO, SQLite и маскирование, ограничения production, токены и повторы, точные байты подписи, журналы, TraceX, избранное и миграции. `tests/deployment` проверяет установку, откат и реальные ACL временных файлов при замоканных вызовах службы. Это не заменяет проверку установки и CryptoPro на целевом сервере.

```powershell
dotnet build src/CrptWorkbench.Web/CrptWorkbench.Web.csproj --no-restore -m:1 -p:UseSharedCompilation=false
```
