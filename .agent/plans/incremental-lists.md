# Постепенное раскрытие списков по 100 записей

Этот ExecPlan ведётся по `.agent/PLANS.md`. Пользователь утвердил добавление порций по 100 во всех потенциально длинных списках.

## Purpose / Big Picture

Пользователь видит первые 100 записей и добавляет следующие кнопкой под списком. Уже показанные записи остаются. Последняя кнопка указывает остаток и исчезает после окончания. Экспорт и бизнес-действия охватывают полный набор.

## Surprises & Discoveries

До изменений история добавляла по 50, документы ограничивались последними 200, файловый предпросмотр — завершёнными заданиями до 1000. Изменение только Razor не обеспечило бы доступ к хвосту.

Обзор обнаружил гонку polling с append, удаление временного файла во время чтения и скрытый requested path после100 siblings. Исправлены версиями загрузки, отменой/ожиданием reader перед удалением и приоритетом requested child в каждой ветви. Старый тест ожидал запрета preview после1000; заменён проверкой всех1001 кодов. Debug build при работающем экземпляре встретил Windows file lock; после остановки повторная сборка прошла.

## Decision Log

Решение 2026-10-02: единая порция 100, добавление вместо замены страниц. Основание: прямой выбор пользователя. Для известных полных наборов — локальное раскрытие; для файлов и SQLite — продолжение от курсора. Схема и сетевые интеграции не меняются.

## Outcomes & Retrospective

Реализация завершена: общие компоненты, 100-записные порции SQLite и файлов, вложенные списки, дерево, формы и история. Версия 1.25.0. Проверено 582 теста, 0 failed, 0 skipped; Web и Release сборки без предупреждений и ошибок. Браузер подтверждает 100/200/250, клавиатуру, фильтр, saved result, history100/200/253, дерево и width380. Интерактивный file chooser оказался ненадёжным: операции инструмента долго зависали. Файлы >1000 и TraceX проверены автоматизированно, реальная SQL-система не использовалась.

## Context and Orientation

Domain содержит порты хранилищ, Application сервисы, Infrastructure SQLite и файлы, Web компоненты Blazor. UI не обращается к хранилищам напрямую. Общие контролы будут в `src/CrptWorkbench.Web/Components`, слой порций в Domain. Файловый курсор означает позицию чтения, SQLite курсор — последнюю запись в стабильной сортировке.

## Validation and Acceptance

Размеры 0,1,99,100,101,200,250 должны показывать корректные порции без дублей и пропусков. Проверить независимые вложения, профиль, фильтр, устаревшие загрузки, повтор после ошибки, SQLite после 200 и файл после 1000. В браузере нажать несколько раз и проверить узкую ширину, клавиатуру, дерево, историю. Автоматизированные тесты доказывают чтение и полный экспорт; HTTP 200 не считается доказательством интерактивности.

## Idempotence and Recovery

Нет миграций и сетевых изменений. Не удалять пользовательские данные и не затрагивать соседние проекты. Ошибка порции сохраняет уже показанные данные; повтор использует тот же курсор. Генерируемые файлы остаются игнорируемыми.

## Interfaces and Dependencies

ShowMore получает VisibleCount, TotalCount (необязательный), HasMore, Loading, Disabled и OnMore. IncrementalList<TItem> получает Items, ChildContent и ResetKey; локальный лимит начинается с 100. Порционное чтение возвращает Items и NextCursor; null означает конец. Сохраняются CancellationToken и проверка профиля. Никаких новых библиотек.
