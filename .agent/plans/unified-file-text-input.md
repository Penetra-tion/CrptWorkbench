# Объединить ввод КМ и TXT в пяти формах

This ExecPlan is a living document maintained under `.agent/PLANS.md`.

## Purpose / Big Picture

Пользователь вводит или вставляет КМ в одно поле и загружает TXT скрепкой в его углу либо перетаскиванием на поле. Обычные формы заменяют текст содержимым файла; массовый запрос создаёт существующую фоновую задачу. Поведение видно на `/console`, `/package-aggregation`, `/package-transformation` и `/code-correction`.

## Surprises & Discoveries

- Формирование упаковок и корректировка кодов уже используют потоковое чтение текста через JS. Это нужно оставить для большого ручного ввода.
- Массовый запрос уже отправляет большой файл в фон без копирования в textarea.
- Для системного выбора файла браузер требует синхронный вызов из события нажатия. JS обработчик кнопки открывает диалог напрямую; обработчик Blazor Server для этого не подходит.

## Decision Log

- Decision: Общая оболочка отвечает только за кнопку, перетаскивание, выбор одного файла и стиль. Чтение файла остаётся у соответствующей страницы.
  Rationale: Это сохраняет ограничения размера, проверки и фоновую обработку.
  Date/Author: 2026-09-28, Codex.
- Decision: JS привязка имеет токен экземпляра и при снятии проверяет его.
  Rationale: При переходе между двумя операциями Console старый компонент не должен удалить обработчик нового компонента с тем же DOM id.
  Date/Author: 2026-09-28, Codex.

## Outcomes & Retrospective

Пять форм используют одну оболочку. Серверные контракты и схема не менялись. Браузер подтвердил выбор TXT в четырёх обычных путях и смену операций; системные drop и большие файлы в UI требуют отдельного ручного прогона, хотя обработка больших файлов покрыта существующим тестом.

## Context and Orientation

Формы находятся в `src/CrptWorkbench.Web/Components/Pages`. Общий компонент `src/CrptWorkbench.Web/Components/FileTextInput.razor` оборачивает существующий textarea и InputFile, а `src/CrptWorkbench.Web/wwwroot/js/file-text-input.js` обрабатывает браузерный выбор и drop. Общий стиль в `src/CrptWorkbench.Web/wwwroot/app.css`. Старый `package-drop.js` остаётся для потокового ввода и анимации предпросмотра.

## Plan of Work

Заменить отдельную область выбора на общий компонент около textarea в каждой форме. У Console привязать компонент к выбранной операции, чтобы переход не оставлял обработчик старой формы. Проверить семантику label и доступность скрепки. Не менять Application, Clients, Infrastructure и миграции.

## Validation and Acceptance

На каждой из пяти форм текст и вставка работают, скрепка открывает выбор TXT с клавиатуры, drop на textarea подсвечивает поле и вызывает ровно одну загрузку. Отмена диалога не меняет текст, повторный выбор того же файла работает, несколько перетащенных файлов дают понятную ошибку, занятая форма не принимает файл. Обычные формы сохраняют текущие ограничения; массовый запрос сохраняет большой файл как фоновую задачу. На узком экране скрепка не перекрывает текст. Сборка без ошибок, тесты без падений.

## Idempotence and Recovery

Правки ограничены UI. Повторная сборка безопасна. При неудаче проверки исправить конкретный компонент или страницу, сохранив существующие обработчики и несвязанные файлы.

## Artifacts and Notes

До правки каждая страница имела отдельную зону выбора файла. Новая оболочка выводит кнопку со значком скрепки и скрытый InputFile внутри общей области textarea.

## Interfaces and Dependencies

`FileTextInput` принимает `ZoneId`, `FileId`, `Disabled`, `Hint`, `ChildContent` и `OnFileChange`. JS модуль присоединяет обработчики к DOM и сообщает компоненту о нескольких файлах. Сервисные интерфейсы и база не меняются.
