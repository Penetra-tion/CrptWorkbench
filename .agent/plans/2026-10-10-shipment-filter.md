# Фильтр текущей отгрузки в массовом запросе кодов

## Purpose / Big Picture

Галочка «Отгружен» в «Запросе по кодам +» оставляет только коды с действующей исходящей отгрузкой от ИНН активного профиля. Входящий возврат исключает код, отмена возврата восстанавливает прежнее положение. Проверка начинается только при включении галочки, распространяется на текст и файловые задания; просмотр, количество и выгрузка используют одно условие. Неясные цепочки обозначаются отдельно и не проходят фильтр.

Этот ExecPlan поддерживается согласно `.agent/PLANS.md`.

## Context and Orientation

`src/CrptWorkbench.Application/TrueApiBulkCodeInfoHandler.cs` получает только /cises/info, а `BulkCodeJobProcessor.cs` сохраняет статус и код в текстовые фрагменты. `src/CrptWorkbench.Infrastructure/BulkCodeFileStore.cs` читает их порциями по 100. `src/CrptWorkbench.Web/Components/Pages/ApiConsole.razor` объединяет статусы для счётчиков, просмотра и выдачи защищённого билета выгрузки. Domain содержит только модели и порты; Application содержит правила; Clients отвечает за разрешённые запросы, Infrastructure — за SQLite, Web — за представление.

Снятие отменяет работу, сохраняя подтверждённые результаты. Интерфейс показывает прогресс, Unknown и порции по 100, выгрузка включает полный выбранный набор.

## Interfaces and Dependencies

Результат содержит код, состояние Shipped/NotShipped/Unknown, время и безопасное пояснение. NotChecked отличается от Unknown: первое означает отсутствие проверки. Сервис проверки работает с ITrueApiClient и AuthenticationContext профиля, возвращает только безопасные структурированные данные. Файловый сервис применяет тот же результат к существующим статусам. Использовать имеющиеся EF Core/SQLite, System.Text.Json, CancellationToken; новых библиотек не требуется.

## Idempotence and Recovery

Миграция только аддитивная, никаких удалений пользовательских данных. Завершённые результаты сохраняются до отмены и продолжаются после неё. Старые форматы не изменяются. Рабочее дерево сохраняется для пользовательского обзора, сгенерированные App_Data/bin/obj остаются игнорируемыми. Production вызовы не выполнять при проверке.

## Surprises & Discoveries

Независимый обзор выявил четыре пограничных случая. Проверка теперь читает все статусы, включая появившиеся в позднем файловом фрагменте; группа furs восстанавливается из истории при файловой проверке; счётчики используют первый сохранённый результат внутри транзакции; выгрузка повторно проверяет область билета при начале перечисления. Регрессии прошли. Также исправлены ссылки УКД на конкретное УПДи, неоднозначная хронология отмен и повторное использование отменённого запроса из кэша.

В существующем bulk workflow отсутствует история документов; checkbox «Оплачен» фильтрует специальный статус APPLIED_NOT_PAID и не должен меняться. Краткие сведения relatedDocId документированы только для LP_SHIP/ACCEPT, поэтому для отмен УПД нужны body.cancelledDocumentId и FIXATION_CANCEL.fixation_document_id. В справочнике FIXATION отменяется статусом CANCELED, а общий справочник использует CANCELLED: поддерживаются оба.
