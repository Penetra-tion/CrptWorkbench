# Карточки кодов и плашки статуса документа

Этот ExecPlan поддерживается по .agent/PLANS.md.

## Purpose / Big Picture

В API Console и истории пользователь видит вертикальные карточки кодов вместо широкой таблицы. Состояние документа читается по цветной плашке с текстом и значком; ошибки находятся в отдельном блоке.

## Context and Orientation

src/CrptWorkbench.Web/Components/Pages/CodeInfoResultView.razor и DocumentStatusResultView.razor используются и ApiConsole, и History. src/CrptWorkbench.Web/wwwroot/app.css задаёт обе темы. Application содержит существующие переводы статусов и ErrorTexts с фильтрацией пустых/повторных ошибок. Новая логика классифицирует только оформление и остаётся в Web.

## Plan of Work

Заменить таблицу кодов карточками с шапкой, полным кодом, GTIN и владельцем. Подробности сохранить в трёх секциях, раскрывать автоматически только одиночный результат. Для INTRODUCED использовать зелёный, EMITTED/APPLIED синий, APPLIED_NOT_PAID жёлтый, остальные нейтральный; ошибка поиска красная. Для документов CHECKED_OK зелёный, CHECKED_NOT_OK/PARSE_ERROR/PROCESSING_ERROR красный, IN_PROGRESS и известные WAIT-статусы жёлтые, ACCEPTED зелёный, остальные нейтральные. Непустые ошибки всегда дают красную плашку. Добавить ResultPresentationTests для классификации и реального рендеринга компонентов через HtmlRenderer.

    dotnet build src/CrptWorkbench.Web/CrptWorkbench.Web.csproj --no-restore -m:1 -p:UseSharedCompilation=false
