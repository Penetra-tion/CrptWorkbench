# Загрузка кодов из TraceX по SQL

This ExecPlan is a living document and must be maintained according to `.agent/PLANS.md`.

## Purpose / Big Picture

Пользователь вставляет запрос чтения к сохранённой базе TraceX и загружает один столбец кодов или две колонки пар упаковок в существующие формы. Большая выборка кодов готовится как отдельное фоновое задание и отправляется на проверку только после отдельного нажатия.

## Milestones

Первый этап создаёт сервис чтения, который принимает профиль и один запрос SELECT, возвращает количество строк, предпросмотр и временный файл. Проверка: тестовый SQL Server и PostgreSQL возвращают строки, а изменяющие запросы отклоняются до выполнения.

Второй этап подключает импорт к формам кодов и упаковок. Проверка: пользователь видит первые строки, выбирает заменить либо добавить, затем использует обычную проверку строк или отправку.

Третий этап позволяет подготовить файловое задание из большой SQL-выборки, пережить перезапуск и отдельно начать проверку. Проверка: до нажатия запуска нет исходящих CRPT-запросов.

## Surprises & Discoveries

- Рабочее дерево уже содержит пользовательские изменения во многих целевых файлах; их нужно сохранять.
- Существующий `BulkCodeFileService.UploadAsync` сразу создаёт состояние `Queued`; для SQL требуется отдельное `Ready`.
- Профильная строка подключения доступна только через `ISecretStore`; SQL и пароль не попадают в историю. Необходимо отдельное подтверждение на реальных тестовых базах, которых в текущем окружении нет.

## Decision Log

- Решение: первый столбец результата содержит код, а для упаковок второй содержит родительский код. Причина: выбор пользователя. Дата: 2026-09-29.
- Решение: SQL не сохраняется; данные применяются по выбору «Заменить» или «Добавить». Причина: выбор пользователя. Дата: 2026-09-29.
- Решение: фоновая проверка начинается отдельным действием. Причина: выбор пользователя. Дата: 2026-09-29.
- Решение: исходный файл SQL импорта живёт только до применения/закрытия панели; массовое задание копирует его в существующее долговременное хранилище. Причина: чистое восстановление после перезапуска без повторного SQL. Дата: 2026-09-29.

## Outcomes & Retrospective

Реализация интегрирована. Release-сборка прошла без предупреждений, 439/439 тестов успешны. Отдельный локальный экземпляр вернул HTTP 200 для `/`, `/console`, `/history`, `/settings`, `/package-aggregation`, `/package-transformation` и `/code-correction`; серверный журнал не содержит необработанных ошибок. В браузере на тестовом профиле подтверждены кнопка импорта, окно SQL, отклонение DELETE до подключения к базе и отсутствие горизонтальной прокрутки при ширине 380 px. Проверка на реальных SQL Server/PostgreSQL базах осталась за пределами локального окружения: тестовых серверов и учётных записей только для чтения нет.

## Context and Orientation

Подключение профиля хранит `ProfileService` в `src/CrptWorkbench.Application/WorkbenchServices.cs`, пароль хранится в `ISecretStore`. `src/CrptWorkbench.Infrastructure/TraceXConnectionTester.cs` создаёт SQL Server и PostgreSQL соединения. Формы находятся в `src/CrptWorkbench.Web/Components/Pages`. Файловые задания используют `src/CrptWorkbench.Application/BulkCodeFileService.cs` и `src/CrptWorkbench.Domain/BulkCodeJob.cs`.

## Plan of Work

Добавить Domain-порт чтения базы и Application-сервис, который получает подключение текущего профиля через защищённое хранилище и создаёт временный результат. Infrastructure реализует команды чтения с отменой и тайм-аутом. Web предоставляет общее окно SQL и соединяет результат с существующими обработчиками ввода. Для массовых кодов подготовленный файл сохраняется в `IBulkCodeFileStore`, а запись получает состояние `Ready`, которое обработчик игнорирует до отдельного запуска.

## Idempotence and Recovery

Повторная загрузка создаёт новый результат, не меняя исходную базу. При ошибке удалять неполный временный файл. Незавершённый запрос после перезапуска не повторять автоматически.
