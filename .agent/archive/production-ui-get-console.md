# Перевести интерфейс на единый боевой контур и переработать GET-консоль

This ExecPlan is a living document. The sections `Progress`, `Surprises & Discoveries`, `Decision Log`, and `Outcomes & Retrospective` must be kept up to date as work proceeds.

План поддерживается по правилам `../PLANS.md`.

## Purpose / Big Picture

После изменения пользователь больше не выбирает sandbox или production: интерфейс и профиль показывают один боевой контур. При этом до отдельного согласования адресов, авторизации и контрактов реальные запросы не отправляются; текущие mock-клиенты остаются безопасной локальной симуляцией и честно обозначаются в интерфейсе. Сайт получает светлую и тёмную темы, сворачиваемую боковую навигацию, заметное действие возврата и плавные анимации. GET-операции в API Console вводятся одинаково в двух режимах: обычный режим показывает распарсенный понятный результат, а технический — полный HTTP-обмен.

## Surprises & Discoveries

- Observation: Git-корень находится в родительском каталоге `D:/Артём/Projects/C#`, а весь каталог `СZHELPER` отображается как untracked.
  Evidence: `git rev-parse --show-toplevel` вернул родительский каталог, а `git status --short` показал `?? ./` среди множества соседних проектов. Поэтому проверка изменений будет выполняться по точному списку файлов внутри `СZHELPER`, без операций над соседними каталогами.
- Observation: Первый повторный build был заблокирован уже запущенным экземпляром CRPT Workbench, удерживавшим DLL web-проекта.
  Evidence: MSBuild сообщил MSB3021/MSB3027 для процесса `CrptWorkbench.Web`; после штатной остановки только этого процесса та же команда завершилась с 0 warnings и 0 errors.
- Observation: Microsoft Testing Platform в ограниченной Windows sandbox не может подключиться к локальному named pipe.
  Evidence: первый тестовый запуск завершился `UnauthorizedAccessException` из `NamedPipeClientStream`; разрешённый запуск вне sandbox выполнил 2 теста успешно за 1.894 s.

## Decision Log

- Decision: Удалить переключатель окружений из пользовательского и прикладного потока, но сохранить значение `Production` в журнале для совместимости с уже созданной SQLite-схемой.
  Rationale: Существующая база имеет обязательную колонку Environment. Постоянное значение даёт production-only поведение без разрушительного пересоздания пользовательской базы.
  Date/Author: 2026-09-14 / Codex
- Decision: Не регистрировать реальные HTTP-адаптеры на этом этапе.
  Rationale: Пользователь определил целевой боевой контур, но ещё не задал точные endpoint'ы, схему авторизации и контракт GET. Mock-only граница должна сохраняться до отдельного, проверяемого включения интеграции.
  Date/Author: 2026-09-14 / Codex
- Decision: Для GET оставить одинаковую форму ввода в обычном и техническом режимах, различая только представление результата.
  Rationale: Это прямо соответствует описанному пользовательскому сценарию и не усложняет ввод техническими полями, которые формирует адаптер.
  Date/Author: 2026-09-14 / Codex

## Context and Orientation

`src/CrptWorkbench.Web/Components/Layout/MainLayout.razor` формирует левую панель и верхнюю строку. `src/CrptWorkbench.Web/wwwroot/app.css` содержит все визуальные стили. `src/CrptWorkbench.Web/Components/Pages/ApiConsole.razor` строит форму операций и результат. `src/CrptWorkbench.Application/Operations.cs` описывает операцию и выполняет её, а `src/CrptWorkbench.Application/DemoOperations.cs` создаёт текущие запросы. `src/CrptWorkbench.Clients/MockClients.cs` возвращает локальный ответ и не выходит в сеть. `src/CrptWorkbench.Domain/Model.cs` хранит профиль и журнал истории.

Боевой контур здесь означает единственную пользовательскую конфигурацию без sandbox-варианта. Локальная симуляция означает, что операция строится в форме боевого сценария, но результат создаётся mock-клиентом, а сетевой вызов не выполняется.

## Plan of Work

Сначала модель профиля и прикладные сервисы будут сведены к production URL и production secret key. `WorkbenchContext` перестанет хранить переключаемое окружение, а исполнитель всегда запишет `CrptEnvironment.Production` для совместимости журнала.

Затем layout получит кнопки назад, сворачивания панели и темы. Небольшой файл `src/CrptWorkbench.Web/wwwroot/app.js` будет хранить тему и состояние панели в браузере и применять их до интерактивной инициализации Blazor. CSS-переменные зададут обе темы; переходы, hover/press-анимации и появление контента будут отключаться при системной настройке reduced motion.

После этого descriptor операции получит HTTP method. Три lookup-операции будут формировать GET с query-параметром и пустым body. API Console оставит одинаковые поля ввода для обоих режимов, покажет плоское понятное представление JSON в обычном режиме и полный request/response в техническом. Секции технического ответа будут сворачиваемыми.

Наконец будет выполнена документированная сборка, запуск приложения, HTTP-проверка маршрутов `/`, `/console`, `/history`, `/settings` и ручной вызов операции через UI, если браузерный сеанс доступен. Логи будут проверены на необработанные исключения и на отсутствие реального сетевого вызова.

## Concrete Steps

Рабочий каталог для всех команд: `D:\Артём\Projects\C#\СZHELPER`.

Восстановить зависимости:

    dotnet restore CrptWorkbench.sln -p:RestoreUseStaticGraphEvaluation=true

Собрать web-проект:

    dotnet build src/CrptWorkbench.Web/CrptWorkbench.Web.csproj --no-restore -m:1 -p:UseSharedCompilation=false

Запустить приложение:

    dotnet run --project src/CrptWorkbench.Web/CrptWorkbench.Web.csproj --no-build

Запустить focused tests (в ограниченной Windows sandbox тестовый runner может потребовать запуск вне неё):

    dotnet test --project tests/CrptWorkbench.Tests/CrptWorkbench.Tests.csproj --no-build --no-ansi --no-progress --output Detailed

## Validation and Acceptance

На широком экране кнопка сворачивания должна уменьшать боковую панель до полосы с иконками, а повторное нажатие — возвращать подписи. Состояние сохраняется после обновления страницы. Кнопка темы переключает светлый и тёмный набор цветов и также сохраняет выбор. Кнопка назад возвращает на предыдущий раздел либо на обзор, если внутренней истории нет.

В layout и настройках отсутствует selector Sandbox/Production. В профиле редактируется один URL для каждой системы, помеченный как боевой. На обзорной странице ясно сказано, что конфигурация боевая, но транспорт пока локальный mock.

В API Console обычный и технический режимы имеют одинаковые поля. После GET-выполнения обычный режим показывает именованные значения результата без JSON, а технический показывает method, URL, status, duration, correlation ID, headers и body. История сохраняет GET и замаскированные заголовки. Ответ содержит `X-CRPT-Workbench-Mock: true`, что доказывает отсутствие реального вызова.

## Idempotence and Recovery

Правки исходников и повторные сборки безопасны. Существующая SQLite-база не удаляется. Производственные колонки профиля уже существуют в прежней схеме, а обязательная колонка Environment продолжит заполняться значением Production. Если запуск оставляет процесс, он завершается штатно через Ctrl+C; файлы App_Data, bin и obj не включаются в перечень результата.

## Interfaces and Dependencies

Razor-компоненты обращаются к нему через `IJSRuntime`, не управляя DOM напрямую.
