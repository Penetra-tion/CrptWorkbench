# Развёртывание CRPT Workbench с боевым True API

Эта инструкция устанавливает CRPT Workbench как самодостаточную Windows-службу. Приложение слушает только `http://127.0.0.1:5080`, поэтому открыть его можно в браузере внутри RDP-сеанса сервера. В промышленный Честный Знак разрешены `POST /cises/info` и чтение сведений о документе `GET /api/v4/true-api/doc/{docId}/info`; для Национального каталога — чтение собственной карточки `GET /v3/feed-product` и её разрешительных документов `POST /v4/rd-info-by-gtin`. Для СУЗ разрешено чтение квитанций документа по GUID через `GET /api/v3/receipts/receipt` с отдельным клиентским токеном; демонстрационный статус заказа остаётся Mock.

## Что потребуется

- Windows Server x64 с актуальными обновлениями и 64-разрядной PowerShell 5.1 или новее.
- CryptoPro CSP, установленный и лицензированный на сервере.
- Сертификат УКЭП зарегистрированного пользователя организации вместе с закрытым ключом в `Cert:\LocalMachine\My`.
- Служба по умолчанию работает от встроенной учётной записи компьютера `LocalSystem`; отдельная пользовательская учётная запись не требуется.
- Исходящий HTTPS-доступ к `markirovka.crpt.ru:443`. Входящий firewall-порт для Workbench не нужен.
- Учётная запись организации в промышленном ЛК ГИС МТ и подключённая товарная группа для проверяемого КИ.

Не копируйте PFX, PIN или закрытый ключ в каталог приложения, ZIP-пакет, `appsettings*.json` либо репозиторий.

## 1. Подготовить CryptoPro и сертификат

Подпись выполняется в памяти через Windows CryptoAPI, которая по привязке сертификата передаёт операцию установленному CryptoPro CSP. Хранилище остаётся `LocalMachine/My`, закрытый ключ не экспортируется. Challenge кодируется в UTF-8 без добавленного BOM и без изменения пробелов/переводов строк; временный файл не создаётся. Флаг подавления интерфейса не устанавливается, то есть криптопровайдеру разрешён запрос PIN (`silent false`). Это не делает Windows-службу интерактивной: диалог из LocalSystem может быть недоступен, а вызов может ожидать его.

Установите CryptoPro CSP из официального дистрибутива и активируйте лицензию. Импортируйте сертификат и привяжите контейнер закрытого ключа через штатные средства CryptoPro. Сертификат должен находиться в хранилище компьютера, а не текущего пользователя.

В повышенной PowerShell-сессии проверьте сертификат, заменив значение на настоящий thumbprint:

    $thumbprint = 'ВАШ_ОТПЕЧАТОК_БЕЗ_ПРОБЕЛОВ'
    Get-ChildItem -LiteralPath "Cert:\LocalMachine\My\$thumbprint" |
        Select-Object Subject, Thumbprint, NotBefore, NotAfter, HasPrivateKey

Ожидается `HasPrivateKey = True`, а текущая дата должна попадать в период действия. Через `certlm.msc` или средства CryptoPro проверьте, что закрытый ключ/контейнер доступен встроенной учётной записи `SYSTEM`. Для устойчивой работы службы контейнер не должен требовать диалога, который недоступен из служебного сеанса, даже при разрешённом `silent: false`.

## 2. Собрать пакет

На машине сборки из корня репозитория выполните:

    PowerShell -ExecutionPolicy Bypass -File .\deploy\windows\Build-Package.ps1

Сценарий восстановит зависимости, соберёт web-проект, запустит тесты и создаст self-contained пакет:

    artifacts\windows\CrptWorkbench-win-x64.zip

Рядом в выводе будет SHA-256. Перенесите ZIP на сервер и повторно вычислите `Get-FileHash`; хэши должны совпасть. Пакет не содержит БД, Data Protection keys, сертификаты, PFX или локальные настройки.

## 3. Установить службу

Полностью распакуйте ZIP в отдельный временный каталог; не запускайте сценарий внутри архива. Откройте PowerShell от имени администратора в распакованном каталоге и выполните:

    .\Install-Service.ps1

Сценарий:

- устанавливает бинарники в `C:\Program Files\CrptWorkbench`;
- хранит SQLite и Data Protection keys в `C:\ProgramData\CrptWorkbench`;
- снимает с файлов пакета метку блокировки, которая может появиться после загрузки или переноса ZIP;
- сохраняет стандартное наследование прав `Program Files`, разрешает `SYSTEM` чтение/запуск и Administrators полный доступ;
- изолирует `ProgramData`, оставляя полный доступ только `SYSTEM`/Administrators;
- задаёт окружение приложения `ASPNETCORE_ENVIRONMENT=Production`, loopback URL и каталог данных; режим интеграций берётся из конфига;
- включает автоматический запуск и три попытки восстановления после сбоя;
- создаёт источник Windows Event Log и проверяет `/health/live`.

По умолчанию служба запускается от имени `LocalSystem`, поэтому пароль вводить не нужно. При обновлении установщик сначала восстанавливает стандартные права старого каталога программы, чтобы администратор мог создать резервную копию. Если обновление прервётся, а служба до него работала, установщик попытается вернуть предыдущие бинарники и снова запустить службу. Для предварительного просмотра действий поддерживается `-WhatIf`.

## 4. Настроить профиль и проверить авторизацию

Новая установка по умолчанию работает в `Mock`. В установленном
`C:\Program Files\CrptWorkbench\appsettings.json` параметр `Crpt:Mode` принимает:
`Mock` — все интеграции локальные даже при реальных адресах; `Production` — реальные
True API, НК и статус документа СУЗ; демонстрационный статус заказа остаётся Mock. Для шагов авторизации ниже явно установите
`"Mode": "Production"` и выполните `Restart-Service CrptWorkbench` от администратора.
Для локальной симуляции оставьте `"Mode": "Mock"`; сертификат и доступ к CRPT не нужны.
`ASPNETCORE_ENVIRONMENT=Production` определяет окружение ASP.NET Core, а не режим интеграций.

Комментарии `//` в конфиге поддерживаются приложением и диагностикой установщика,
в том числе в Windows PowerShell 5.1. Не удаляйте сами параметры. При обновлении
установщик сохраняет существующие `appsettings*.json` вместе с комментариями;
новые пояснения можно посмотреть в `app/appsettings.json` распакованного пакета.

### Если старая служба игнорирует Mock

Старый установщик записывал `Crpt__Mode=Production` в окружение службы, и это
перекрывало конфиг. Повторная установка новым сценарием удаляет это переопределение,
сохраняя остальные пользовательские переменные. Без переустановки можно убрать
только эту переменную в повышенной PowerShell-сессии (для другого имени службы
измените `$serviceName`):

    $serviceName = 'CrptWorkbench'
    $serviceKey = "HKLM:\SYSTEM\CurrentControlSet\Services\$serviceName"
    $oldEnvironment = @(Get-ItemPropertyValue -LiteralPath $serviceKey -Name Environment -ErrorAction SilentlyContinue)
    $newEnvironment = @($oldEnvironment | Where-Object { $_ -and $_ -notmatch '^Crpt(__|:)Mode=' })
    if ($newEnvironment.Count) {
        New-ItemProperty -LiteralPath $serviceKey -Name Environment -PropertyType MultiString -Value $newEnvironment -Force | Out-Null
    } else {
        Remove-ItemProperty -LiteralPath $serviceKey -Name Environment -ErrorAction SilentlyContinue
    }
    Restart-Service -Name $serviceName

Перед перезапуском задайте нужный `Mode` в установленном конфиге. При Mock в UI
должны отображаться три индикатора MOCK, а ответы операций содержать
`X-CRPT-Workbench-Mock: true`. Если остаётся БОЙ, проверьте другие источники
переопределения: `appsettings.Production.json`, системную переменную `Crpt__Mode`
и аргументы запуска. Изменение режима требует перезапуска службы.

В RDP-сеансе сервера откройте:

    http://127.0.0.1:5080/settings

Выберите профиль или создайте новый, укажите название и ИНН организации из 10 или 12 цифр. Выберите сертификат из `LocalMachine/My`, сохраните профиль и нажмите «Проверить».

Приложение выполнит только безопасную авторизацию: получит challenge через `/auth/key`, сформирует прикреплённую PKCS#7 Base64-подпись через Windows CryptoAPI и привязанный CryptoPro CSP и вызовет `/auth/simpleSignIn`. Исходная строка challenge включается внутрь CMS без изменения байтов. Токен хранится только в памяти не более девяти часов и никогда не показывается в UI или истории.

После успешной авторизации выполните итоговую проверку:

    .\Verify-Deployment.ps1 -RequireReady

Ожидаются работающая служба, только loopback listener, HTTP 200 от liveness и `ready: true`. Если readiness сообщает об отсутствии профиля или сертификата, исправьте настройки и повторите команду.

## 5. Выполнить первый реальный запрос

Откройте `http://127.0.0.1:5080/console`, выберите True API → «Информация о кодах» и вставьте один известный реальный КИ в нормализованном виде без скобок `(01)` и `(21)`. После выполнения:

- ответ не должен содержать `X-CRPT-Workbench-Mock`;
- технический режим должен показать `POST https://markirovka.crpt.ru/api/v3/true-api/cises/info`;
- `/history` должен содержать тот же запрос с `Authorization: Bearer ********`;
- Национальный каталог должен выполнять поиск собственной карточки с Bearer-токеном выбранного профиля; статус документа СУЗ использует отдельное подключение и сертификат, а демонстрационный статус заказа остаётся Mock.

При HTTP 403 проверьте, что сертификат принадлежит пользователю нужной организации и у организации подключена товарная группа. При ошибке подписи проверьте доступ `SYSTEM` к контейнеру и отсутствие интерактивного PIN. При 401 приложение само обновит токен и повторит `/cises/info` ровно один раз.

## 6. Диагностика

Проверить службу и последние события:

    Get-Service CrptWorkbench
    Get-WinEvent -FilterHashtable @{ LogName = 'Application'; ProviderName = 'CRPT Workbench' } -MaxEvents 50 |
        Select-Object TimeCreated, LevelDisplayName, Message

Проверить, что порт доступен только локально:

    Get-NetTCPConnection -State Listen -LocalPort 5080 |
        Select-Object LocalAddress, LocalPort, OwningProcess

Допустимы только `127.0.0.1` или `::1`. Приложение не логирует HTTP-тела, Authorization, challenge, подпись или токен.

## 7. Обновление и откат

Соберите и перенесите новый ZIP, полностью распакуйте его и снова выполните `Install-Service.ps1` из PowerShell, запущенной от имени администратора. Установщик остановит только `CrptWorkbench`, нормализует права старого каталога программы, сохранит предыдущие бинарники в `C:\ProgramData\CrptWorkbench\backups\<timestamp>`, заменит приложение и проверит liveness. БД и ключи не удаляются.

Для отката к последней резервной копии из каталога распакованного пакета выполните от имени администратора:

    .\Restore-PreviousVersion.ps1

Исправленный установщик обновляет путь службы через `Win32_Service.Change` и показывает код Windows при отказе. Общий сценарий `AccessControl.ps1` записывает разрешения напрямую через Windows ACL API, без `icacls`: владельцы, группы и настройки аудита не меняются. SYSTEM/Administrators получают явные разрешения на каждом существующем объекте; каталоги передают их новым файлам. Права наследования снимаются только с корня каталога данных после добавления явных разрешений в тот же дескриптор, а не рекурсивно с резервных копий. Сохранённые разрешения перечитываются и проверяются; конфликтующий явный запрет для этих SID останавливает сценарий. Ручной откат восстанавливает доступ к данным, ключам и резервным копиям и проверяет чтение всех файлов выбранной копии до удаления установленной версии. Старые резервные копии, включая возможный legacy-каталог `App_Data`, сохраняются; удалять их для устранения ошибки доступа не нужно. Символические ссылки и junction внутри изменяемого дерева не поддерживаются: сценарий останавливается, чтобы не менять права за пределами выбранного каталога.

Если предыдущая попытка установки завершилась ошибкой настройки службы и отказом доступа при откате, перенесите новый пакет в отдельный каталог, распакуйте его и выполните обновлённый `Restore-PreviousVersion.ps1` для восстановления последней копии. После проверки восстановленной службы повторите `Install-Service.ps1`. Не используйте скрипты из старого ZIP.

Если служба уже восстановлена вручную и отвечает на `/health/live`, откат повторять не нужно: полностью распакуйте новый ZIP в отдельную папку и выполните `Install-Service.ps1` от имени администратора. Не переносите только один скрипт: `AccessControl.ps1` должен лежать рядом с установщиком и сценарием отката.

Сценарий заменяет только бинарники и не меняет `C:\ProgramData\CrptWorkbench`. Перед ручным восстановлением runtime-данных остановите службу и создайте отдельную копию всего каталога `C:\ProgramData\CrptWorkbench`.

## Граница безопасности

Боевой режим разрешает только HTTPS-запросы к `markirovka.crpt.ru:443` и маршруты `/api/v3/true-api/auth/key`, `/auth/simpleSignIn`, `/cises/info` и `GET /api/v4/true-api/doc/{docId}/info` с заданными HTTP-методами. Для последнего разрешены только `body=false`, `content=false` и необязательный `pg`; остальные query string, другой порт, host или endpoint блокируются до отправки. Redirect отключён. Изменение URL в профиле не влияет на реальный transport. Разрешённые методы Национального каталога описаны выше. Для СУЗ дополнительно разрешены только `GET /api/v3/receipts/receipt?omsId={uuid}&resultDocId={uuid}` на `suzgrid.crpt.ru:443` и `POST /api/v3/true-api/auth/simpleSignIn/{omsConnection}` на разрешённом хосте True API; используются отдельный токен и HTTP-клиенты без перенаправлений.

## Файловые журналы

Serilog записывает `server` (сервер, бизнес-операции, интеграции) и `client` (действия и ошибки интерфейса Blazor). Оба журнала находятся на сервере; Console и Application EventLog не используются. По умолчанию серверные файлы лежат в `Crpt:DataDirectory\logs\server\server-YYYYMMDD.log`, клиентские — в `Crpt:DataDirectory\logs\client\client-YYYYMMDD.log`. Данные журналов сохраняются при обновлении службы и не включаются в ZIP.

В `appsettings.json` раздел `WorkbenchLogging` независимо управляет серверным журналом (`ServerEnabled`), журналом интерфейса (`UiEnabled`), HTTP (`HttpEnabled`), CryptoPro (`CryptoProEnabled`) и событиями команд SQLite (`SqlQueriesEnabled`). По умолчанию первые четыре включены, SQL-команды выключены. При выключенных SQL-командах ошибки БД остаются в журнале. Для команд и ошибок выводятся только безопасные сведения о событии; SQL-текст и значения параметров не записываются. `HttpDetailsEnabled`, `ExceptionDetailsEnabled` и `CryptoProviderMessagesEnabled` по умолчанию выключены. Подробности HTTP включают путь, безопасные заголовки и статус, но не тела. Настройки применяются к новым событиям без перезапуска. Старый `Serilog:FullLoggingEnabled` больше не используется.

Полный режим может записать `Authorization`, токены True API, подпись, challenge, ИНН, коды маркировки, строки подключения и другие чувствительные данные. Включайте его только на время одной диагностической попытки, не передавайте такой журнал без защищённого канала и после получения нужной ошибки верните значение `false`. Отключение не очищает ранее записанные файлы.

В `appsettings.json` раздел `Serilog:LevelSwitches` содержит `$server` и `$client` с уровнем `Information`. Можно независимо установить `Debug`, `Warning`, `Error` или `Fatal`; существующие переключатели и overrides категорий обновляются без перезапуска. `Serilog:MinimumLevel:Default=Verbose` допускает детализацию обоих каналов; повышение общего уровня ограничивает оба журнала. `MinimumLevel:Override` управляет категориями Microsoft/System (по умолчанию Warning).

В каждом `Serilog:WriteTo:…:Args:configureLogger:WriteTo:0:Args` задаются `path`, `rollingInterval`, `fileSizeLimitBytes`, `rollOnFileSizeLimit`, `retainedFileCountLimit` и `outputTemplate`. Относительный path разрешается относительно каталога данных; абсолютный используется непосредственно. Пути, фильтры, формат и ротация требуют перезапуска. По умолчанию ротация ежедневная и по 20 МБ, максимум 31 файл для каждого журнала. При настройке абсолютного пути выдайте учётной записи службы право записи в этот каталог.

CorrelationId операции записывается в серверные события, исходящий transport и клиентский результат. Логи не содержат тела HTTP, авторизацию или секретные поля. Исключения содержат только тип; произвольные сообщения и свойства системных библиотек заменены безопасным `Framework event` с EventId. Ошибки circuit Blazor направляются в client. Подробные маскированные обмены доступны в истории приложения.

При ошибке подписи нажмите «Проверить» один раз и откройте свежий `C:\ProgramData\CrptWorkbench\logs\server\server-*.log`. Категория `CrptWorkbench.Infrastructure.CryptoProCertificateSignatureService` пишет на уровне Information начало, разрядность процесса, признак LocalSystem, хранилище LocalMachine/My и silent-режим; после проверки сертификата — наличие привязки к закрытому ключу, числовой OID алгоритма и выбранный backend. Для ГОСТ ожидается `Signing backend selected: Windows CryptoAPI`. При сбое на уровне Error записываются этап (`CertificateLookup`, `CertificateValidation`, `ComputeSignature` или `EncodeSignature`), тип исходного исключения и HRESULT в виде `0xXXXXXXXX`. В безопасном режиме в этих записях нет subject/отпечатка сертификата, имени контейнера, PIN, challenge, подписи, токена, сообщения или стека исключения. Запись `HasPrivateKey=true` означает привязку к ключу, а не доказательство успешного доступа или подписи. HRESULT помогает уточнить причину; сам по себе он не всегда однозначно определяет неисправность.
